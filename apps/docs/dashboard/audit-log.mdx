---
title: "Audit log"
description: "See who changed what in an environment, from the dashboard or with an API key."
---

The audit log records every change made in an environment: who made it, what changed, when, and from where. Admins read it in the dashboard under **Settings**, on the **Audit log** tab.

## What an entry contains

| Field | Meaning |
|---|---|
| Actor | Who made the change. The actor kind is `user` (a dashboard member), `api_key`, `connect_session` (your customer, in the connect UI), `support` (SecureFabric support staff) or `system`. |
| Action | What happened, such as `connection.created`. |
| Target | The object that changed, with its kind and ID. |
| Detail | Extra context, such as the scopes of a new API key. Never secrets. |
| IP address, user agent, request ID | Where the request came from. Quote the request ID to support. |
| Time | When it happened. |

An entry is written in the same transaction as the change it records, so every change has an entry and no entry exists for a change that didn't happen. Entries can't be edited or deleted, and are kept for at least a year.

## Recorded actions

| Area | Actions |
|---|---|
| API keys | `api_key.created`, `api_key.revoked` |
| Environments | `environment.created`, `environment.updated` |
| Team | `member.invited`, `member.role_changed`, `member.removed` |
| Organizations | `organization.created`, `organization.updated`, `organization.deleted` |
| Integrations and vendor apps | `integration.created`, `integration.updated`, `integration.deleted`, `vendor_app.created`, `vendor_app.updated`, `vendor_app.deleted` |
| Connections | `connection.created`, `connection.updated`, `connection.metadata_updated`, `connection.reset`, `connection.purged` |
| Connect flow | `connect_session.created`, `connect.installation_bound`, `connect.installation_rejected` |
| Syncs | `job.requested`, `job.cancelled` |
| Webhooks | `webhook_endpoint.created`, `webhook_endpoint.updated`, `webhook_endpoint.deleted`, `webhook_endpoint.secret_rotated`, `webhook_delivery.replayed` |
| Data | `action.requested`, `passthrough.requested` |
| SecureFabric support | `support.access` |

`connect.installation_rejected` means someone tried to bind a GitHub App installation they can't access. SecureFabric refused it.

## Access by SecureFabric support

SecureFabric staff can open your environment only to help with an issue, and must state a reason each time. Each access is recorded as `support.access` with that reason, under actor kind `support`.
