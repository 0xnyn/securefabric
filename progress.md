## Deviations from the plan (with reasons)

- `sync.ingress_delivery` is not range-partitioned: the `(vendor_app_id, delivery_id)` uniqueness must hold across days; retention is a daily delete instead.
- The KEK is asymmetric (X25519) instead of symmetric, so the API can create environments (wrap) but never unwrap (part 3 trust boundary holds with a local master key).
- The monotonic clock lives in `data.object_clock` per (connection, object type), not on `stream_head`, because two streams can write one object type (GitHub repos+branches, SANDBOX findings+exports).
- Leen facts that differ from the plan's assumptions are listed in `docs/research/leen-v2-and-workos.md` (e.g. Leen has no `X-ORGANIZATION-ID`; ours is additive).
- The API role reaches operational tables only through narrow `SECURITY DEFINER` functions (`obs.system_status()`, `obs.flush_api_calls()`, the operator functions) instead of table grants, so `sf_api` keeps no direct rights on cross-tenant data.
- `payload_unreadable` is an alert the plan does not list: rows sealed with a key no longer loaded are unrecoverable, so the re-encryption job raises it (with a runbook) rather than failing silently or stalling.
- The plan names `securefabric-cdk dryrun|record`; they live in `securefabric-admin` because opening a live connection's credentials needs the vault and the database, which the CDK must not depend on.
- SANDBOX has no website, so OAuth manifests may say `authorize_url: local:/path`: the platform serves that page through the connector's in-process vendor (`/v1/connect/local/...`), accepting only the connector's own callback as `redirect_uri`.
- `GET /v1/status` is readable without credentials but returns only the summary; workers, queues and counts need a key or session, and alert subjects (other tenants' ids) are operator-only.
- A verification that crashes (not a classified vendor error) is retried by Absurd; on the final attempt the connection shows INTERNAL_ERROR (owner PLATFORM), `connection.create.failed` is emitted and an alert raised. Exception text is never copied anywhere (it can carry credentials); the traceback stays on the Absurd run. Testing a never-activated connection retries its creation.
